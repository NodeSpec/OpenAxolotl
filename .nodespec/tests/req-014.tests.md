# Test Plan: REQ-014 - Curated discovery and reliable package installation

## Testing Objectives

**Requirement:** Curated discovery and reliable package installation
**Category:** functional
**Description:** The player-facing hub exposes only owner-approved adventures, preserving a cohesive single-player game. Creator-kit entries are discovered separately in the parent-facing workshop. Private drafts and submission discussions never become a public game feed.

## Acceptance Criteria

Criterion text lives HERE once; every section below cites the AC id.

- **AC-REQ-014-1** [automated] [PENDING] Only owner-authorized, approved, compatible and non-withdrawn playable package versions appear as installable adventures, with reviewed author credits and compatibility information. Drafts, rejected submissions and asset-only approvals cannot appear as playable releases; the child-facing game contains no unmoderated upload feed or public chat.
- **AC-REQ-014-2** [automated] [PENDING] Downloads are staged, verified against the approved release record and activated atomically; interruption, invalid content or failed verification preserves the previous working install.
- **AC-REQ-014-3** [automated] [PENDING] A missing or incompatible world shows an actionable unavailable state while the hub and other installed worlds remain playable.
- **AC-REQ-014-4** [automated] [PENDING] Official and previously installed supported content remains playable without a network connection or AI account.
- **AC-REQ-014-5** [automated] [PENDING] Install verification checks a release signature against the bundled trusted publisher key and the package digest before activation; unsupported keys, tampering or downgrade outside the compatibility policy preserve the prior installation.
