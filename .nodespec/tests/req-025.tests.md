# Test Plan: REQ-025 - Balance and Tuning Configuration

## Testing Objectives

**Requirement:** Balance and Tuning Configuration
**Category:** technical
**Description:** Many acceptance criteria across the player systems assert a "configured modifier", "bounded window", or "configured magnitude" without anywhere defining the values. Without a single named home for those numbers, tests have nothing to assert against and every system invents its own constants. This requirement establishes one authoritative, data-driven tuning surface covering capability-loss modifiers (swim speed, boost duration, climb height), default lives per attempt, dash charge and recharge rates, Gill Mod durations and cooldowns, enemy debuff magnitudes and windows, and restoration resource costs. Values live in data rather than code so they can be tuned without recompiling and so an AI agent or contributor can adjust balance without touching system logic. Worlds may override a documented subset; everything else stays global to keep the game coherent across forks.

## Acceptance Criteria

Criterion text lives HERE once; every section below cites the AC id.

- **AC-REQ-025-1** [automated] [PENDING] All balance values are defined in data files rather than as constants in system code
- **AC-REQ-025-2** [automated] [PENDING] The tuning surface covers capability-loss modifiers, default lives per attempt, dash charge and recharge, Gill Mod durations and cooldowns, enemy debuff magnitudes and windows, restoration resource costs, grapple range, camera smoothing thresholds, mutation loadout duration, momentum retention across grammar transitions, and maximum retry duration
- **AC-REQ-025-3** [automated] [PENDING] Every value carries a documented name, unit, and permitted range
- **AC-REQ-025-4** [automated] [PENDING] Changing a tuning value alters observable behavior with no code change and no recompile
- **AC-REQ-025-5** [automated] [PENDING] The set of values a world may override through the Level Contract is explicitly enumerated, and an override outside that set is rejected
- **AC-REQ-025-6** [automated] [PENDING] Loading a tuning file with a missing or out-of-range value fails with a named error rather than silently defaulting
- **AC-REQ-025-7** [automated] [PENDING] Every tuning key cited by another requirement's acceptance criteria exists in the tuning data with a documented unit and permitted range, and a test fails when a cited key is absent
