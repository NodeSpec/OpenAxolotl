# Test Plan: REQ-011 - A bounded, versioned downloadable content format

## Testing Objectives

**Requirement:** A bounded, versioned downloadable content format
**Category:** technical
**Description:** Local Godot source may be freely iterated, but published level packages contain only supported declarative content and approved component/asset references. Separate asset/character submissions become versioned kit entries through review; they are not arbitrary runtime code. A Godot scene or PCK is not assumed safe merely because it is called content.

## Acceptance Criteria

Criterion text lives HERE once; every section below cites the AC id.

- **AC-REQ-011-1** [automated] [PENDING] The machine-readable package schema defines identity/version, contract/runtime/kit compatibility, sections, spawn, checkpoints, objectives, finish, asset references, save schema, credits and integrity metadata. Its manifest pins exact dependency versions and digests, and approved playable releases reference only approved reusable asset/character versions.
- **AC-REQ-011-2** [automated] [PENDING] Export and load reject scripts, native extensions, executable resource/scene references, unknown behavior IDs, invalid parameter ranges and paths outside the package namespace.
- **AC-REQ-011-3** [automated] [PENDING] A conforming starter exports and loads through the same runtime content path used for approved community levels.
- **AC-REQ-011-4** [automated] [PENDING] A proposed mechanic requiring new executable behavior is routed to a separate reviewed core-code change rather than smuggled into a downloadable level.
- **AC-REQ-011-5** [automated] [PENDING] Trusted editor authoring may use scripts and scenes, but export compiles supported placements into the downloadable data schema; the runtime never loads a submitted executable scene or script as content.
