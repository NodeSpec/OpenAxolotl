# Test Plan: REQ-008 - Four architectural responsibilities and a versioned World API

## Testing Objectives

**Requirement:** Four architectural responsibilities and a versioned World API
**Category:** technical
**Description:** Separate core runtime, reusable Level Kit, world content and authoring/distribution. Reuse the working Godot systems incrementally; do not rewrite the engine. API and package schemas must be concrete before code is built against them.

## Acceptance Criteria

Criterion text lives HERE once; every section below cites the AC id.

- **AC-REQ-008-1** [automated] [PENDING] Shared runtime modules contain no world-specific placement coordinates or world-owned spawn lists; each world owns its layout, objectives and placements.
- **AC-REQ-008-2** [automated] [PENDING] Levels access checkpoint, collectible, restoration, encounter and completion services only through the documented versioned public World API; static checks reject private cross-boundary access.
- **AC-REQ-008-3** [automated] [PENDING] The contract requires spawn, checkpoints, finish, controller/runtime compatibility and save integration, with explicit optional defaults and migration rules.
- **AC-REQ-008-4** [manual] [PENDING] An ownership map assigns each source file to one primary component and documents cross-component contracts before implementation changes.
- **AC-REQ-008-5** [automated] [PENDING] A single runtime composition point wires shared services; level content never writes the player physics root, imports private runtime members or registers arbitrary scripts through the downloadable content path.
- **AC-REQ-008-6** [manual] [PENDING] Document the migration from the current script-bearing level contract and global no-network policy to separate trusted local-authoring and data-only download paths; catalog networking is isolated from world behavior and offline gameplay remains supported.
