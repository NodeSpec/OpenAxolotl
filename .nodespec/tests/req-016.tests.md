# Test Plan: REQ-016 - Explicit code, asset and contributor rights

## Testing Objectives

**Requirement:** Explicit code, asset and contributor rights
**Category:** business
**Description:** Distinguish open-source code licensing, asset/model/texture/music/level redistribution and remix permissions, contributor consent and official branding. Independent forks remain possible under the code license; official inclusion and branding permission are separate owner-controlled decisions. Externally generated assets need reviewed provenance.

## Acceptance Criteria

Criterion text lives HERE once; every section below cites the AC id.

- **AC-REQ-016-1** [automated] [PENDING] The exportable asset catalog excludes assets lacking a recorded approved redistribution/remix status and required attribution.
- **AC-REQ-016-2** [manual] [PENDING] Review and publish the code license, asset reuse terms, generator/third-party obligations, contributor permissions and separate official branding/publication policy before inviting public reuse or submissions. Parent-facing terms explain that open-source reuse or a fork does not confer official approval, and public credit can use a parent-approved alias without publishing a child's personal details.
- **AC-REQ-016-3** [automated] [PENDING] Each published package retains its credited asset manifest and required attribution through installation and updates.
