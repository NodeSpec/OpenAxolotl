# Test Plan: REQ-024 - Input and Control Scheme

## Testing Objectives

**Requirement:** Input and Control Scheme
**Category:** functional
**Description:** The control scheme is the concern that drove the PC-only platform decision and until now had no home requirement. The axolotl carries an unusually wide verb set for a platformer: two full movement grammars, dive, hop, climb, tongue grapple, water-powered dash, bubble boost, plus equipping and activating Gill Mods. Fitting that onto a comfortable scheme without modal overload is a real design problem, not a formality. The scheme must be context-sensitive so that water and land verbs can share bindings where they do not conflict, must support both keyboard-and-mouse and gamepad on PC, and must be fully remappable per the accessibility constraint. Input handling belongs to the controller's published interface so that worlds never read raw input directly.

## Acceptance Criteria

Criterion text lives HERE once; every section below cites the AC id.

- **AC-REQ-024-1** [automated] [PENDING] Every player verb is bound in both a keyboard-and-mouse scheme and a gamepad scheme
- **AC-REQ-024-2** [automated] [PENDING] Bindings are context-sensitive by movement grammar, so water-only and land-only verbs may share a physical input without conflict
- **AC-REQ-024-3** [automated] [PENDING] Every binding is remappable, and remapped bindings persist across sessions
- **AC-REQ-024-4** [automated] [PENDING] Rebinding rejects a conflicting assignment within the same context rather than silently overriding it
- **AC-REQ-024-5** [automated] [PENDING] Switching between keyboard and gamepad mid-session is handled without requiring a restart, and on-screen prompts follow the active device
- **AC-REQ-024-6** [automated] [PENDING] Worlds read player intent through the controller interface and never read raw input directly
- **AC-REQ-024-7** [manual] [PENDING] The full verb set is playable without modal overload or uncomfortable finger contortion
