# Test Plan: REQ-012 - Automated content checks and reproducible builds

## Testing Objectives

**Requirement:** Automated content checks and reproducible builds
**Category:** technical
**Description:** Conformance validates the submitted asset, character or level against its declared profile and gives actionable diagnostics. Level checks cover actual traversal and progression. Automated success is evidence for human review, never permission to publish; historical test results are not copied as fresh proof.

## Acceptance Criteria

Criterion text lives HERE once; every section below cites the AC id.

- **AC-REQ-012-1** [automated] [PENDING] CI runs level/schema checks, asset checks, public-API/static rules, representative real-input route tests and the relevant core regressions from a documented clean setup.
- **AC-REQ-012-2** [automated] [PENDING] Validation detects missing markers, unreachable required progression, gate bypasses, capsule-sized containment gaps and invalid habitat placement.
- **AC-REQ-012-3** [automated] [PENDING] Package validation enforces file-count, compressed/uncompressed size and allowed-resource limits, safe paths and integrity checks before activation. It rejects missing, unapproved, withdrawn or digest-mismatched dependencies for official publication and produces diagnostics identifying the exact submission and dependency.
- **AC-REQ-012-4** [automated] [PENDING] Each acceptance criterion records a current result or an explicit manual review; skipped, stale or historical checks are not reported as passing.
- **AC-REQ-012-5** [automated] [PENDING] Test plans use one initial binding scenario per automated acceptance criterion and a separate manual checklist; performance measurements use a rendered build and visual quality is never inferred from a headless pass.
- **AC-REQ-012-6** [automated] [PENDING] Route tests drive the production controller with real input through entrance, pools, underwater turns and every section; teleporting between checkpoints cannot count as traversal proof.
