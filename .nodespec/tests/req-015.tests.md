# Test Plan: REQ-015 - Asset Contract, Asset Library and AI-Art Provenance

## Testing Objectives

**Requirement:** Asset Contract, Asset Library and AI-Art Provenance
**Category:** technical
**Description:** The art-side sibling of the Level Contract, and — since "build your level out of our assets" is half the open-source promise — the library itself.

THE CONTRACT. A specification any character, creature, or prop asset must conform to in order to enter the repo. Contributors generate art with whatever external AI tool they choose (offline authoring — no in-editor generation plugin at MVP), then drop conforming output into the repo. The contract defines required file types, directory layout and naming convention, resolution and format specs, alpha-channel handling, and a required provenance.json per asset. Provenance records author, generation method, and applicable license terms for EVERY asset; AI-generated assets additionally record the generation tool and prompt.

THE LIBRARY IS A DELIVERABLE, NOT A BYPRODUCT. This is the part the new vision adds. Today's assets exist because the official levels needed exactly them; a person building a level of their own composes from what is there, and finds it either sufficient or empty. So the shipped set has to be broad enough that a new level can be built without authoring any art, and CATALOGUED — a browsable index naming every asset, its category, its footprint and what it is for. An uncatalogued library is a directory tree, and a newcomer cannot compose from a directory tree.

PROVENANCE IS NOW LOAD-BEARING, NOT BOOKKEEPING. Telling someone "build with our assets" is issuing a grant, and a grant cannot be issued over geometry whose terms belong to an external generator. Assets whose provenance records external terms of service must be resolved or replaced before the contribution story is published; this requirement is the place that surfaces them, and REQ-021 is the place the decision is made.

## Acceptance Criteria

Criterion text lives HERE once; every section below cites the AC id.

- **AC-REQ-015-1** [automated] [VERIFIED] Asset Contract specifies required file types, resolution/format constraints, and alpha-channel handling per asset category
- **AC-REQ-015-2** [automated] [VERIFIED] Asset Contract specifies the asset directory layout and naming convention
- **AC-REQ-015-3** [automated] [VERIFIED] Every asset requires a provenance.json recording author, generation method, and applicable license terms
- **AC-REQ-015-4** [automated] [VERIFIED] AI-generated assets additionally record the generation tool and the prompt used; these fields are not required for hand-authored assets
- **AC-REQ-015-5** [automated] [VERIFIED] provenance.json has a defined schema whose generation-method field distinguishes ai-generated from hand-authored, and which conditionally requires the tool and prompt fields accordingly
- **AC-REQ-015-6** [manual] [PENDING] Contract documents the style and art-direction expectations a human maintainer reviews against
- **AC-REQ-015-7** [manual] [PENDING] A contributor can produce a conforming asset from the Asset Contract document alone
- **AC-REQ-015-8** [automated] [PENDING] A generated, checked-in catalogue lists every shipped asset with its category, triangle count, texture footprint and intended use, and a test fails when an asset is added or removed without the catalogue being regenerated
- **AC-REQ-015-9** [automated] [PENDING] Every asset whose provenance records license terms originating outside this repository is listed as such by the validator, so the set needing a licensing decision or replacement is enumerated rather than discovered
- **AC-REQ-015-10** [manual] [PENDING] The shipped library is broad enough that a new level in a setting the official worlds do not cover can be built from it without authoring new art, demonstrated by building one
